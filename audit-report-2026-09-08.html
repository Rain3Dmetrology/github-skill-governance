Repository audit

GitHub Skill Governance · 2026-09-08 · contract, security, architecture, configuration and remote-effect evidence

Conclusion: P1 platform controls and the tested Broker route are real, but the repository is not yet a production C-grade authorization boundary. Normal owner merge authority bypasses the Broker, and dispatch and approval share one identity.

Audit basis

  • 71 tracked files before the audit change; 62 deterministic tests plus the repository validator.
  • Remote GitHub readback and negative/positive Broker canaries.
  • Three parallel audit roles; two independently confirmed the critical/high authorization findings.
  • pip-audit and actionlint were unavailable locally; those checks are explicitly degraded, not claimed as passed.

Decision

  1. Keep Release, tag, Secret and Ruleset authority frozen.
  2. Do not present the single-owner Broker as an account-compromise boundary.
  3. Proceed with P2 only as deterministic local validation and PR-scoped output.
  4. Require a dedicated machine identity and separate approver before production C closure.
